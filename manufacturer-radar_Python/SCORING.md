# v1.1 评分、收录与归属规则

搜索结果首先进入候选记录。软件必须实际读取厂家或供应商详情页，取得全称、相关产品或经营业务和厂家身份依据，保留详情页链接、名称原文、详情页核验原文及收录依据，才计入正式厂家结果。仅搜索标题、摘要、排行榜、新闻、聚合列表、验证码页面或未读取的链接不计入厂家数量。

正式收录要求 `page_verified`、完整名称、有效 `verification_url`、非空收录依据，以及同一详情页的“详情页核验”和“名称”证据同时存在。缺少电话不会直接排除已经识别的厂家，但会降低信息完整度。详情页核验只表示已访问页面并识别该页面所述身份与业务，不表示工商认证或实地验厂。

通过收录条件后的总分为以下项目相加，再减去待核实负面线索扣分，最后限制在 0–100。

| 项目 | 分值 |
| --- | ---: |
| 已实际进入详情页并依据页面内容识别厂家，有核验原文和详情页链接 | 30 |
| 从已读取详情页提取到完整厂家名称 | 20 |
| 主营产品或经营范围及详情页原文证据 | 15 |
| 地区或地址及详情页原文证据 | 5 |
| 格式符合规则、可回溯到已核验页面的公开电话 | 10 |
| 详情页名称原文及来源链接 | 5 |
| 已核验页面电话原文及来源链接 | 5 |
| 记录搜索引擎、查询关键词、前 3 页内页码及原始链接 | 5 |
| 至少两个搜索引擎有收录结果 | 3 |
| 负面状态为“本轮未发现”或“发现待核实线索” | 2 |
| 待核实负面指称 | 每个不同来源 URL 减 15，最多减 30 |

评分只用于信息完整度及线索排序，不是工商认证、企业资质、信用评级或对负面指称的事实认定。多个搜索引擎可能收录同一篇内容，多个引擎出现不等于独立核实。

电话可来自厂家详情页，或另行实际读取、确认相同完整名称的联系页。联系页须同时保留访问过的 URL、“联系页核验”“名称”和“电话”证据；只有外部网页的一串号码或未确认主体的联系页不加电话分。电话的实际归属和有效性仍需人工核对。页面没有明确广告标签时，广告状态为未知；投放广告本身不扣分。

未通过详情页收录条件的候选线索，名称、候选链接、搜索文本电话和原始搜索来源最多分别得 5、10、5、5 分，合计上限 25。这些分数仅供审计，候选不会作为已找到的厂家展示。旧版历史中的原始链接记录仍完整保存，但正式厂家数量按新条件重新计算。

“未检查”表示本轮未执行检查；“检查受限”表示因访问限制、时间、取消或身份不足等原因无法完成；“本轮未发现”只描述本轮有限检索范围；“发现待核实线索”保留链接与原文，需人工核实。

名称按全称精确比较（仅归一化宽度、空白、拉丁字母大小写）。公司不因同电话、同域名或同一平台而合并；同一页面提取到两个不同完整名称也不会合并。URL 只归一化主机、默认端口、参数顺序和 UTM 跟踪参数，保留可表示不同企业的路径、其他参数及片段。

负面线索需在同一句摘要中出现相同完整厂家名称与实际负面指称关键词；不使用搜索关键词本身作证据，不将“无投诉”“投诉电话”“非诈骗”等中性或否定短语当作负面。自动文本匹配仍可能漏检或误判，应以原始来源人工核对。

CSV 使用 UTF-8 BOM；CSV 和 Excel 对不可信文字防止公式注入。汇总导出包含主营、经营范围、地区、地址、详情来源验证、详情页、收录依据和原始搜索链接。Excel 分别保留厂家汇总、搜索记录、证据明细、收录核验及本评分说明；超长证据保留在续页。JSON 和 SQLite 保存完整厂家数据、候选搜索记录、访问/筛选统计和采集日志，原始链接不会因未通过收录而丢失。
